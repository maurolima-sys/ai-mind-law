# Routes

TanStack Start uses **file-based routing**. Every `.tsx` file in this directory
defines a route. Do **not** create `src/pages/`, `src/routes/_app/index.tsx`, or
`app/layout.tsx` — those are Next.js / Remix conventions. The only root layout
is `src/routes/__root.tsx`.

## Conventions

| File                     | URL                                                     |
| ------------------------ | ------------------------------------------------------- |
| `index.tsx`              | `/`                                                     |
| `about.tsx`              | `/about`                                                |
| `users/index.tsx`        | `/users`                                                |
| `users/$id.tsx`          | `/users/:id` (dynamic — bare `$`, no curly braces)      |
| `posts/{-$category}.tsx` | `/posts/:category?` (optional segment)                  |
| `files/$.tsx`            | `/files/*` (splat — read via `_splat` param, never `*`) |
| `_layout.tsx`            | layout route (renders children via `<Outlet />`)        |
| `__root.tsx`             | app shell — wraps every page; preserve `<Outlet />`     |

`routeTree.gen.ts` is auto-generated. Don't edit it by hand.

The `/evaluation` route contains a browser-local evaluation workspace. It
requires the existing Supabase session and is enabled in development by default.
Set `VITE_ENABLE_EVALUATION_DASHBOARD=false` to disable it locally; production
builds return 404 unless `VITE_ENABLE_EVALUATION_DASHBOARD=true` is explicitly
configured. This client-side session guard is not invite-only authorization.
The local records are not encrypted or synchronized and must not contain secrets
or tender content. Collaborative access requires a separate authorization design.
