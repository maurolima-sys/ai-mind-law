# Guidelines — AI Mind Law

## Code Quality Standards

### TypeScript
- Strict mode is enforced (`strict: true` plus `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`, `noImplicitReturns`). Every value must be explicitly typed or safely inferred — no implicit `any`.
- Use `import type` for type-only imports (seen in `sampleTender.ts`, `__root.tsx`).
- Union string literal types are preferred over enums:
  ```ts
  export type Severity = "Critical" | "High" | "Medium" | "Low";
  export type ProcessingMode = "demo" | "local" | "cloud";
  ```
- Export companion constant arrays alongside union types for iteration:
  ```ts
  export const SEVERITIES: Severity[] = ["Critical", "High", "Medium", "Low"];
  ```
- Interfaces over type aliases for object shapes (`Evidence`, `Requirement`, `Analysis`, etc.).
- `as const` for fixed lookup objects:
  ```ts
  const THEMES = { light: "", dark: ".dark" } as const;
  ```

### Naming Conventions
- React components: PascalCase (`ChartContainer`, `NotFoundComponent`, `RootShell`).
- Hooks: camelCase prefixed with `use` (`useIsMobile`, `useChart`).
- Files: kebab-case for hooks (`use-mobile.tsx`), kebab-case for services (`documentProcessing.ts`), kebab-case for UI components (`chart.tsx`).
- Constants: SCREAMING_SNAKE_CASE (`MOBILE_BREAKPOINT`, `DEMO_DOC_ID`, `THEMES`).
- IDs in data objects: short prefixed strings (`"r1"`, `"d1"`, `"s1"`, `"k1"`).

### Formatting (Prettier)
- Print width: 100 characters.
- Semicolons: required.
- Quotes: double quotes (`"`).
- Trailing commas: always (including function parameters).

## Structural Conventions

### React Components
- Functional components only — no class components.
- `React.forwardRef` for all UI primitives that need DOM ref forwarding; always set `.displayName`:
  ```ts
  ChartContainer.displayName = "Chart";
  ```
- `React.useId()` for generating stable unique IDs within components.
- `React.useMemo` for expensive derived values inside render (e.g., tooltip label computation).
- Context pattern: create context with `null` default, throw a descriptive error in the consumer hook if context is missing:
  ```ts
  const ChartContext = React.createContext<ChartContextProps | null>(null);
  function useChart() {
    const context = React.useContext(ChartContext);
    if (!context) throw new Error("useChart must be used within a <ChartContainer />");
    return context;
  }
  ```

### Hooks
- Responsive breakpoint detection uses `window.matchMedia` with an event listener, not polling:
  ```ts
  const mql = window.matchMedia(`(max-width: ${MOBILE_BREAKPOINT - 1}px)`);
  mql.addEventListener("change", onChange);
  return () => mql.removeEventListener("change", onChange);
  ```
- Initial state for SSR-safe hooks is `undefined`, coerced to `boolean` on return (`!!isMobile`).

### Styling
- All class composition goes through `cn()` from `@/lib/utils` (`twMerge(clsx(...))`).
- Tailwind CSS v4 CSS variables for theming — colours referenced as `text-foreground`, `bg-background`, `text-muted-foreground`, `border-border`, etc.
- Arbitrary CSS variable injection via `style` prop for dynamic colours:
  ```tsx
  style={{ "--color-bg": indicatorColor } as React.CSSProperties}
  ```
- Tailwind child selectors (`[&_.recharts-layer]:outline-none`) used in complex UI components to style third-party library internals.

### Routing (TanStack Router)
- Every route exports a single `Route` constant — no default exports from route files.
- Root route uses `createRootRouteWithContext<{ queryClient: QueryClient }>()()`.
- `head()` must be set per route; never add `og:image` / `twitter:image` at the root level.
- `shellComponent` (`RootShell`) renders the full HTML document; `component` (`RootComponent`) wraps providers.
- `<Outlet />` must remain in `RootComponent` — removing it breaks all child routes.
- `routeTree.gen.ts` is auto-generated by the TanStack Router Vite plugin — never edit manually.

### Services
- Plain TypeScript modules (no classes) exported as named functions.
- Server-only modules must use the `*.server.ts` naming convention or `@tanstack/react-start/server-only` — never import `server-only` (Next.js package).

### Data / Types
- All domain types live in `src/lib/types.ts`.
- Evidence objects always carry `{ page: number | null; excerpt: string | null; verified: boolean }` — page is 1-based, null when unknown.
- Demo/sample data is isolated in `src/data/` and must carry a visible disclaimer label (`DEMO_LABEL`).

## Error Handling
- SSR errors: `src/server.ts` wraps the TanStack Start server entry, catches h3-swallowed errors (JSON body `{ unhandled: true, message: "HTTPError" }`), and returns a rendered HTML error page.
- Client errors: `ErrorComponent` in `__root.tsx` calls `reportLovableError` in a `useEffect` and exposes a "Try again" button that calls `router.invalidate()` + `reset()`.
- Never compress response bodies in server routes — hosting compresses at the edge.

## Vite / Build
- Do not add plugins already provided by `@lovable.dev/vite-tanstack-config` (TanStack devtools, tanstackStart, viteReact, tailwindcss, tsConfigPaths, nitro, env injection, path alias, deduplication, error logger, sandbox detection).
- Never set `ssr.external` or `resolve.external` — the Cloudflare Worker has no runtime module resolution.
- Never add compression plugins — edge handles it.

## Testing
- Test files co-located under `src/test/` or alongside source as `*.test.tsx` / `*.spec.tsx`.
- `src/test/setup.ts` imports `@testing-library/jest-dom` matchers — always import this in setup, not in individual tests.
- Use `jsdom` environment (configured in `vitest.config.ts`).
